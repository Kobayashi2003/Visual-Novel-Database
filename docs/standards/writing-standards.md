# Writing a standard

Applies to every document in this directory, including this one.

- State what the reader **should do**. If a sentence would still be true when
  nobody acts on it, it is not a rule — cut it.
- Do not describe the codebase. The code already records what exists; a standard
  records what to do with it.
- Do not argue for a rule. Give a reason only where the rule is baffling without
  one, and give it in a single clause.
- Define a term only where the rules depend on it, and only as far as they need.
- Say every point fully, in as few words as it takes. There is no length limit
  and no licence to pad.
- Keep one subject per document, and name the file after that subject.
- Keep the sections disjoint. If a rule fits under two headings, the headings
  are wrong — regroup them.
- Write in English.
